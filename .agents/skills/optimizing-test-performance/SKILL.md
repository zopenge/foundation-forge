# 测试性能诊断与优化

以真实墙钟与失败机制决定优化方向。局部加速、增量收据命中和完整验收是三种不同结论。

开始前读取[实验记录](references/experiments.md)，查保留、撤回、设计否决和未证实的条目；再对照当前 SHA 与差异。记录是历史证据，不代替当前授权、代码或 [AGENTS.md](../../../AGENTS.md)。

## 定位成本

先读取现成运行的终态、检查模式、源码指纹、UTC、测试计数、阶段墙钟、真实 worker 峰值及受管收尾。已有任务未结束时接续原 session；证据不足不等于应重新启动整包。

同时记录工具执行模式与审批依据，核对比较样本的权限上下文；状态文件未记录时标为未知，不能仅凭相同命令推定一致。遇真实权限拒绝先停止并报告，通过受支持的审批机制处理，不更换终止机制或修改系统权限来绕过。

受限上下文缺少测试所需 OS 终止能力时，先核同一自建 fixture 操作的现有授权与批准上下文，用最小单例验证能力，再考虑恢复全量；不要反复跑全量。申请只限已授权且已证实受阻的操作，以工具实际审批结果为准，其他任务继续使用其适用的默认权限。

| 需要确认 | 仓库入口与判断 |
|---|---|
| 全量还是复用 | [验证契约](../../../docs/maintenance/validation.md)、`scripts/check-runner.mjs`、`check-mode.mjs`；核对失效文件、环境、dist 与真实 tarball 摘要 |
| 调度还是用例成本 | `scripts/check-full.mjs`、`run-workspace-coverage.mjs`；比较阶段墙钟与同一阶段测试文件区间，累计子进程时间不能直接相加 |
| 重复准备还是必要回归 | [测试分层映射](../../../packages/release-vercel/tests/README.md)；列出每种失败机制、真实入口及夹具准备，区分实际阶段重跑与门禁重新观察 |
| 采样可信度 | [进程采样说明](../../../packages/release-vercel/evaluation/README.md)；父子区间和身份查询会重叠，宿主存活时间包含授权、持久化和 payload |

检查完整路径：构建次数、打包/安装、消费者矩阵、脚本隔离、覆盖率汇总、测试文件负载与增量失效。先算候选的收益上限；不要只盯最慢文件或把一个候选的 No-Go 外推所有方案。

磁盘准入失败时，先核原门槛和本任务资源，再限定到明确历史运行，跳过共享缓存与未知链接；不要直接扩容或降低准入。目录逻辑长度不是可回收物理空间，同卷移动或回收站也不能记作释放空间。外部操作后空间恢复，只报告观察结果，不能归功于本任务。

## 选择与证伪

每次选择一至两个候选，写清「固定输入 → 根因证据 → 算法改变或测试边界重组 → 保留的不变量 → 预期收益上限 → 最小反例/实验 → 停止条件」。先运行能够否定方案的定向实验，再保留有收益且质量等价的最小改动。

重组夹具时，让组件只承担其输入准备；真实 Git、进程、持久化、崩溃恢复、错误时点和独立消费者的证据由明确用例继续承载。缓存必须从空 checkout 可重建、隔离动态资源，不能把旧 `.tmp` 或合成成功作为前提。算法合并须证明同一操作内语义等价，跨 await、命令或持久化边界的新鲜性不能用一次早先观察替代。

例如，预算夹具可以直接创建自有目录与真实锁，再调用生产原子写入；完整受管发布仍验证 Git 准入。相反，几条 Git 查询共享一个前置门禁，会改变查询之间管理目录被跟踪时的拒绝时点。

## 验收与留档

涉及 Windows 验收隐藏或取消时，另读 [Windows 验收边界](references/windows-check-boundaries.md)。区分固定版本 pnpm 的进程级适配、正常 shell/native 孙进程、协作取消与根 Job。先验证入口、PATH 和环境隔离的传递；不得把外层退出、参数检查通过或审批过一个旧单例当成整链已隐藏、已清空或允许恢复全量。

保留现有两个真实测试 worker 上限、隐藏窗口、超时、覆盖率、真实 tarball 和父侧退出/后代关闭证据。历史访问拒绝与进程归属边界见实验记录；技能本身不授予额外权限。

用户报告闪窗或桌面干扰时，先暂停新启动并按当前授权关闭本任务；外层 PID 退出不代表受管后代已结束，须分别记录 session 终态、最后 Job 清空时间及 remainingWorkers。若原链仍继续启动任务，明确披露该区间，不能写成停止请求后没有新子进程。截图标题只能识别窗口类型，不能证明归属；不得操作未核归属窗口或全局枚举进程来补证据。

静态排查逐层跟踪实际启动链：外层 Node、包管理器 lifecycle、cmd/batch 包装、fixture 内联脚本和原生子进程。记录每层 command/stdio/detached/windowsHide 与对应运行时版本；最外层隐藏不向后代构成保证。先读已安装包管理器的底层 spawn 实现，勿把直接调用 JS CLI 当成消除了内部 shell。以同版本 Node/libuv 和系统创建标志解释参数，仍需区分源码风险、真实调用与可见窗口证据。当前指令要求暂停复现时，只读排查和文档验证不触发测试；恢复最小验证前先满足该指令的确认条件。

纯注入检查可在已有隔离运行时中执行已读源码的函数正文或调用表达式，进程和文件系统依赖全部使用不可透传的替身。分别保存原实现失败、回读改动通过及参数等价证据；设计片段的通过不能冒充正式源码已修复，更不能证明真实 Job 或桌面状态。补隐藏参数时保留 argv、stdio、环境、异常和返回语义；检查 preload 是否被现有隔离边界移除，不能为方便传播而削弱该边界。

定向验证使用正式 context/observer，不能以简化入口代替最终验收。首个失败停止该次并定位，保留失败证据；不要反复整包碰运气或用成功路径同步日志改变竞态。技能文档先做结构、链接、编码与检索情景验证；是否运行门禁仍遵循 AGENTS 和本次用户授权，技能不自行豁免。代码改动组合稳定后再做一次原完整门禁。

组件测试即使注入假的 execute，调用前的包管理器定位仍可能依赖父进程环境。直接 Node 回归须核对这些前置依赖；若收到 AggregateError 而日志未展开内层原因，先保留为未定位，不能仅凭外层类型或把断言改为接受任意聚合错误来宣布修复。

临时资源验收单列「创建者 → 精确路径/身份 → 活跃归属 → 正常、失败、取消及超时的收尾」。比较运行前后目录清单与字节，不以 Job 空代替文件已清理。当前可复用的机制是 Job 临时根、fixture 自身 dispose 和 coverage 发布暂存回收；逐项核对调用者是否采用，不能外推为全部资源或宿主崩溃后自动清理。测试自己的假 context 日志也要在确认收尾后删除。

删除边界不能只信任 `realpath(repo/.tmp)`：先核 `.tmp` 本身不是指向仓库外的重解析根；fixture 根也须记录身份并拒绝链接或替换，仅检查 realpath 仍在共同 base 内会允许误删另一 fixture。身份检查与删除间的并发替换仍须单列，不能以普通路径成功掩盖它。

取消/超时探针先核 Provider 的终态契约。当前 `closed/normal` 只表示正常完成；主动终止可为 `unknown/terminated` 且 `empty: true`。须同时保留原始取消错误、父侧空集合、dispose 完成及租约归零，不能要求取消任务伪装成正常成功，也不能只凭 `unknown` 推断仍有后代。探针中途断言失败时，独立记录自有路径是否存在与哨兵内容；未执行的断言仍算未验证，不能用最终清理代替它。

原生复制因祖先元数据读取被拒时，核对 API 调用栈、实际源/目标及权限粒度。Node 对现有目录的读取授权包含子树，不能将元数据批准自动转成整个父树读取；没有可表达的最小范围时保留阻塞，不换复制实现或取消权限模型来让回归通过。
一次父树读取批准不覆盖更高祖先。源和目标均在仓库内也可能触发 `fs.cp` 的防自复制祖先检查；记录完整路径、realpath 和具体拒绝资源后停止，不能沿父目录逐级自动扩大。

必要失败/验收证据与工作产物分开。先写清本次保留项及结束条件，只保留支持当前失败、配对比较与正式交付的必要数据；已被持久摘要和后续验收替代的大产物，仍需核实失效归属并遵守当前删除授权。历史永久删除若需批准，提交精确路径、大小、用途和不可恢复范围，不能按 mtime 扫删。尚未实现有限轮转时明确列为缺项，不宣称长期无累积。

交付先报告真实终态与目标差距，再补证据。更新参考记录时只保留固定 SHA、关键数字、质量边界、结论和重试判据；详细日志留在自有 ignored 目录。全量数值受环境或安装波动影响时，分别报告局部实测与单次全量观测，不宣称稳定因果收益。
